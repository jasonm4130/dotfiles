# Components

What this repo manages. The agent config (Claude Code and Codex) was reset to a minimum on 2026-11-13; the README describes what is left.


- **zsh** — `.zshrc`, `.zshenv`, `.zprofile`. Secrets come from `op-agent inject` via `~/.config/op/load-env.zsh`, sourced by both `.zprofile` (login) and `.zshrc` (non-login interactive), with an unexported `_OP_ENV_TRIED` guard on *attempted* so a locked or offline 1Password warns once and child shells re-ask. `op-agent` (`~/.local/bin/op-agent`) runs the real `op` as the 1Password service account `agents`, whose token sits in the login Keychain (service `op-agents-token`) and is set for that one command only; it reads only the **Agents** and **K3s Runners** vaults, so `env.tmpl` may reference only those. Plain `op` keeps full access through the desktop-app integration (Touch ID). There is no local cache (op-fast was removed 2026-11-21): each shell start costs one 1Password round-trip. The loader **parses** the injected output line by line and assigns with `typeset -gx`; it never `eval`s it, because `op inject` substitutes with no shell escaping (a `$$`, an unbalanced quote or `"; cmd; echo "` in a secret would otherwise expand, abort or execute). References in `env.tmpl` stay wrapped in braces, a secret value may not contain a newline (multi-line secrets use an on-demand `op-agent read`), and the loader saves and restores `xtrace` so `zsh -x -i` never prints secrets.
- **Starship** — prompt config (`~/.config/starship.toml`)
- **mise** — version manager for node/python/rust toolchains, activated two ways on purpose. `.zshrc` runs `mise activate zsh`, which prepends the real install dirs and is what interactive shells use. `.zshenv` separately prepends `~/.local/share/mise/shims`, which is what everything *else* uses — `zsh -c`, git hooks, agent tool calls, any script that never reads `.zshrc`. Without the second half `cargo` is simply not found in those contexts, which reads as a broken toolchain rather than a PATH gap. Upstream documents `mise activate zsh --shims` in `.zprofile` for this, but `.zprofile` covers login shells only and the gap is non-login non-interactive, so it has to be `.zshenv`; the static PATH prepend is used rather than `--shims` because that form forks a mise process on every zsh invocation and this file is on the hot path for all of them (measured: 3.4ms per shell, unchanged). Interactive shells still get the real binaries — `activate` prepends on top of the shims — and both routes honour a repo's `rust-toolchain.toml`, verified as the same pinned version each way. One consequence: `python3` in a non-interactive zsh is now mise's, not `/usr/bin/python3`. `.zshenv` also turns off `EQUALS` and `NOMATCH` when `CLAUDECODE` is set, so `echo === x ===` and unquoted `--include=*.go` work in Claude Code's Bash tool as they would in bash; interactive shells keep both options. Note the launchd jobs do **not** benefit, and do not need to: three of the four are `#!/usr/bin/env bash` and never read `.zshenv` at all, so each already bootstraps its own absolute paths (`brew shellenv`, a literal `/opt/homebrew/bin/chezmoi`, a runtime-resolved `claude`) and `disk-maintenance.sh` sets an explicit PATH that includes the shims directory
- **Language servers** — `lsp-doctor` probes the three servers Claude Code's LSP plugins drive (rust-analyzer, typescript-language-server, pyright) and `--repair` reinstalls what is missing; `run_onchange_after_14-lsp-servers.sh.tmpl` runs the repair whenever the node version or the rust toolchain set moves. Both server failures seen so far were **silent** — the LSP tool starts erroring and grep quietly becomes the fallback — and neither shared a mechanism: a repo pinning a rust toolchain without the `rust-analyzer` component makes rustup's proxy fall back to the mise shim, which resolves back to the proxy (`infinite recursion detected`), while a node major bump orphans the global npm packages tsserver lives in under `node/<version>/lib`. The probe therefore checks that `--version` exits 0 **and** prints something version-shaped: the rust-analyzer shim loop was an executable file on `PATH` that ran, so an existence or exit-status check passes it. `typescript-language-server` stays outside mise deliberately (see the note in `dot_config/mise/config.toml`), which is why its repair is `npm i -g` rather than a mise tool.
- **zoxide** — frecency `cd`, initialised with `--cmd cd` so it shadows the builtin: `cd <substring>` jumps to the highest-ranked match, `cd <real/path>` behaves as before, and `cdi` opens the fzf picker. Its `eval` must stay **last** in `.zshrc` — it wraps whatever `cd` is defined at load time, so anything below that redefines `cd` clobbers it
- **Ghostty** — terminal config (`~/.config/ghostty/config`)
- **Zed** — editor config (`~/.config/zed/`)
- **Fonts** — Monaspace everywhere: both Ghostty and Zed wear the **Xenon** cut (slab-serif, terminal-esque). The generated **Monaspace Neon Radon** family (Neon for code, handwritten Radon for comments via the italic slot — Monokai Pro CE italicizes `comment`) is available but no longer wired up; rebuild it with `monaspace-radon-mix.py` after the Monaspice cask updates if you want it back.
- **Claude Code** — `~/.claude/settings.json`, `~/.claude/CLAUDE.md`, the `quota` skill and the status-line tee. No hooks, rules, custom agents or MCP config.
- **AGENTS.md** — one short `~/.codex/AGENTS.md` for every coding agent; `~/.claude/CLAUDE.md` imports it.
- **Codex** — `~/.codex/config.toml` sets `model = "gpt-6.1-sol"` at medium reasoning effort, and `~/.codex/AGENTS.md` holds the shared agent instructions. Both are chezmoi-managed.
- **Brewfile** — rendered from `.chezmoidata/packages.yaml` (the source of truth for taps/formulae/casks); the bundle script runs `brew trust --tap` for each declared tap first, since Homebrew 6 refuses to load untrusted third-party taps. Declare **leaves only**: naming a package that is merely a dependency sets `installed_on_request`, which permanently exempts it from `brew autoremove`, so the declaration silently pins transitive deps forever and makes later cleanup reclaim far less than it appears to. When auditing size, run `brew cleanup` before pruning anything — the download cache is not counted in `/opt/homebrew` and reclaimed 13.3GB here, more than the entire package prune that followed
- **macOS defaults** — Dock, Finder, keyboard, etc.
- **CI** — GitHub Actions, three jobs on every push/PR. `node-test` runs `node --test tests/*.test.mjs` (script suites) on ubuntu + macOS × Node 20/22. `shellcheck` lints every tracked script **selected by shebang, not extension** — two shipped bash scripts have no `.sh` suffix. `render` runs `chezmoi apply --dry-run` so a broken template fails here instead of on a new machine, then lints the `.sh.tmpl` scripts *after* rendering (Go template directives are not shell, and shellcheck reports them as parse errors). Both new jobs run on ubuntu: the macOS images ship SwiftLint but not shellcheck
