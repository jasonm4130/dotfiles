# Components

What this repo manages, beyond Claude Code (which has [its own page](claude-code.md)).


- **zsh** — `.zshrc`, `.zshenv`, `.zprofile`. Secrets come from `op-fast inject` via `~/.config/op/load-env.zsh`, sourced by both `.zprofile` (login) and `.zshrc` (non-login interactive). A normal tab is both, so the file carries an `_OP_ENV_TRIED` guard and injects once. The guard is on *attempted*, not *succeeded* — otherwise a locked 1Password makes `.zshrc` retry what `.zprofile` just failed, warning twice — and it is deliberately **not** exported, so child shells re-ask and op-fast's TTL still gets to expire a rotated secret. op-fast caches in the macOS Keychain, so persistence across shells and reboots is the Keychain's — the shell only re-exports from it (~30ms warm). **op-fast does not honour shell comments in `env.tmpl`** — it scans the file for secret references by scheme and resolves every one it finds, so a commented-out `export FOO=$(op-fast read …)` example is still fetched and cached on every inject. Two secrets documented there as deliberately not loaded at startup were being loaded at startup for exactly that reason, and because one carried a 15m TTL it expired constantly, making the next shell start pay a full 1Password round-trip and a Touch ID prompt — measured at 6629ms against 28ms for a clean cache hit. That is what "1Password prompts on every new tab" turned out to be. The commented examples now have their scheme broken deliberately; restoring them to literal URIs silently re-adds those secrets to the startup set. Relatedly, per-item TTLs are a trap here: a short TTL does not keep an item out of the warm cache, it only decides how often *everyone else's* shell startup pays for it, so the config now carries a single 24h TTL and anything that genuinely must stay uncached should be read with plain `op` instead. The loader **parses** op-fast's output line by line and assigns with `typeset -gx`; it does not `eval` it. That is load-bearing, not style: `op-fast inject` does raw textual substitution with no shell escaping, so under `eval` a secret containing `$$` was silently replaced by the PID, one containing an unbalanced quote aborted every export after it while leaving the warning branch unreachable, and one containing `"; cmd; echo "` **executed** — verified, with a backticked `touch` creating its sentinel file. For the same reason the references in `env.tmpl` are wrapped in braces: bare `NAME=op://…` lines break op-fast's reference scanner, which then reports `op inject returned 8 values for 4 references`, and the braces leave no wrapper for the parser to strip wrongly. Do not unwrap them. Two consequences to know: a secret value may not contain a newline (any folding rule would swallow the file's own comment block into the preceding variable), so multi-line secrets belong in an on-demand `op-fast read`; and the loader saves and restores `xtrace` around the parse, because `zsh -x -i` previously printed every secret to stderr four times over
- **Starship** — prompt config (`~/.config/starship.toml`)
- **mise** — version manager for node/python/rust toolchains, activated two ways on purpose. `.zshrc` runs `mise activate zsh`, which prepends the real install dirs and is what interactive shells use. `.zshenv` separately prepends `~/.local/share/mise/shims`, which is what everything *else* uses — `zsh -c`, git hooks, agent tool calls, any script that never reads `.zshrc`. Without the second half `cargo` is simply not found in those contexts, which reads as a broken toolchain rather than a PATH gap. Upstream documents `mise activate zsh --shims` in `.zprofile` for this, but `.zprofile` covers login shells only and the gap is non-login non-interactive, so it has to be `.zshenv`; the static PATH prepend is used rather than `--shims` because that form forks a mise process on every zsh invocation and this file is on the hot path for all of them (measured: 3.4ms per shell, unchanged). Interactive shells still get the real binaries — `activate` prepends on top of the shims — and both routes honour a repo's `rust-toolchain.toml`, verified as the same pinned version each way. One consequence: `python3` in a non-interactive zsh is now mise's, not `/usr/bin/python3`. Note the launchd jobs do **not** benefit, and do not need to: three of the four are `#!/usr/bin/env bash` and never read `.zshenv` at all, so each already bootstraps its own absolute paths (`brew shellenv`, a literal `/opt/homebrew/bin/chezmoi`, a runtime-resolved `claude`) and `disk-maintenance.sh` sets an explicit PATH that includes the shims directory
- **Language servers** — `lsp-doctor` probes the three servers Claude Code's LSP plugins drive (rust-analyzer, typescript-language-server, pyright) and `--repair` reinstalls what is missing; `run_onchange_after_14-lsp-servers.sh.tmpl` runs the repair whenever the node version or the rust toolchain set moves. Both server failures seen so far were **silent** — the LSP tool starts erroring and grep quietly becomes the fallback — and neither shared a mechanism: a repo pinning a rust toolchain without the `rust-analyzer` component makes rustup's proxy fall back to the mise shim, which resolves back to the proxy (`infinite recursion detected`), while a node major bump orphans the global npm packages tsserver lives in under `node/<version>/lib`. The probe therefore checks that `--version` exits 0 **and** prints something version-shaped: the rust-analyzer shim loop was an executable file on `PATH` that ran, so an existence or exit-status check passes it. `typescript-language-server` stays outside mise deliberately (see the note in `dot_config/mise/config.toml`), which is why its repair is `npm i -g` rather than a mise tool.
- **zoxide** — frecency `cd`, initialised with `--cmd cd` so it shadows the builtin: `cd <substring>` jumps to the highest-ranked match, `cd <real/path>` behaves as before, and `cdi` opens the fzf picker. Its `eval` must stay **last** in `.zshrc` — it wraps whatever `cd` is defined at load time, so anything below that redefines `cd` clobbers it
- **Ghostty** — terminal config (`~/.config/ghostty/config`)
- **Zed** — editor config (`~/.config/zed/`)
- **Fonts** — Monaspace everywhere: both Ghostty and Zed wear the **Xenon** cut (slab-serif, terminal-esque). The generated **Monaspace Neon Radon** family (Neon for code, handwritten Radon for comments via the italic slot — Monokai Pro CE italicizes `comment`) is available but no longer wired up; rebuild it with `monaspace-radon-mix.py` after the Monaspice cask updates if you want it back.
- **Claude Code** — settings, hooks, agents, MCP config and sounds. See [Claude Code](#claude-code) below.
- **AGENTS.md** — unified AI tool instructions, rendered to per-tool files
- **Codex** — `~/.codex/config.toml` pins `model = "gpt-5.6-terra"`. The CLI's own default is `gpt-5.6-sol`, which inverts the pairing rule in `~/Work/Git/CLAUDE.md` (Terra for automatic review passes, Sol only when named), so without the pin every unflagged `codex exec` quietly bills the expensive reviewer on work routed to the cheap one. Escalate deliberately with `-m gpt-5.6-sol`. `AGENTS.md` also lives in this directory but is **not** tracked — `dot_ai/render.sh` writes it there directly — so `config.toml` is the only chezmoi-managed file under `~/.codex`, and `chezmoi managed | grep codex` returning one line is correct rather than a sign of missing state.
- **Brewfile** — rendered from `.chezmoidata/packages.yaml` (the source of truth for taps/formulae/casks); the bundle script runs `brew trust --tap` for each declared tap first, since Homebrew 6 refuses to load untrusted third-party taps. Declare **leaves only**: naming a package that is merely a dependency sets `installed_on_request`, which permanently exempts it from `brew autoremove`, so the declaration silently pins transitive deps forever and makes later cleanup reclaim far less than it appears to. When auditing size, run `brew cleanup` before pruning anything — the download cache is not counted in `/opt/homebrew` and reclaimed 13.3GB here, more than the entire package prune that followed
- **macOS defaults** — Dock, Finder, keyboard, etc.
- **CI** — GitHub Actions, four jobs on every push/PR. `node-test` runs `node --test tests/*.test.mjs` (hook & script suites) on ubuntu + macOS × Node 20/22. `go-test` vets, gofmt-checks and tests `dot_local/src/claude-hooks` on both OSes — the guards are plain stdin/stdout programs, so a Linux failure would mean the source is not portable even though chezmoi only ever builds it on macOS. `shellcheck` lints every tracked script **selected by shebang, not extension** — two shipped bash scripts have no `.sh` suffix. `render` runs `chezmoi apply --dry-run` so a broken template fails here instead of on a new machine, then lints the `.sh.tmpl` scripts *after* rendering (Go template directives are not shell, and shellcheck reports them as parse errors). Both new jobs run on ubuntu: the macOS images ship SwiftLint but not shellcheck
